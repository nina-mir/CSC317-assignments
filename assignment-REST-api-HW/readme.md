# CSC 317 — Group Project: In-Memory REST API

## Overview

In this assignment, your group will build a **simple in-memory REST API** using **Express (CommonJS)**. Instead of managing colors, your API will manage a dataset related to **your group's e-commerce product** from the term project.

This assignment is based directly on the [REST Colors Mini-API Activity](https://github.com/nina-mir/CSC317-assignments/blob/main/activities/REST-colors/readme.md). You are expected to study that document thoroughly and adapt its patterns to fit your group's product.

---

## What You're Building

Each group sells a different product. Your job is to replace the `colors` dataset with a dataset that represents **your product's inventory**. For example:

- A group selling **sneakers** might store objects like `{ name: "air-max-90", price: 129.99, size: 10 }`
- A group selling **books** might store `{ title: "dune", author: "frank herbert", price: 12.99 }`
- A group selling **coffee** might store `{ name: "ethiopian-yirgacheffe", roast: "light", price: 14.50 }`

Your dataset must have **at least 3 fields per object** and start with **at least 3 seed items** in the array.

---

## Required API Endpoints

You must implement **all five** endpoint types from the REST Colors activity, adapted to your product. The table below uses a generic `product` placeholder — replace it with whatever makes sense for your project.

| Method | Path | Purpose | Status Codes |
|--------|------|---------|--------------|
| `GET` | `/` | Return **all** products | `200` |
| `HEAD` | `/` | Return product **count** via a custom header (e.g., `X-Product-Count`) | `200` |
| `GET` | `/:identifier` | Return a **single** product by name/id | `200` or `404` |
| `POST` | `/add` | **Add** a new product (with validation & normalization) | `201`, `400`, or `409` |
| `DELETE` | `/:identifier` | **Delete** a product by name/id | `204` or `404` |

### Requirements for Each Route

- **GET /**: Return the full array as JSON with status `200`.
- **HEAD /**: Set a custom `X-...-Count` header with the current array length. No response body.
- **GET /:identifier**: Case-insensitive lookup. Return `200` with the object if found, or `404` with `{ "error": "not found" }`.
- **POST /add**: Validate all required fields. Normalize strings (e.g., lowercase names). Return `400` for missing/invalid fields, `409` if a duplicate exists (by name or id), and `201` with the created object on success.
- **DELETE /:identifier**: Return `204` (no body) on success, `404` if not found.

---

## Technical Requirements

- **CommonJS** syntax (`require`, not `import`).
- `express.json()` middleware must be enabled.
- Include **helper/utility functions** for validation and normalization (similar to `isValidHex`, `normalizeName`, etc. in the colors activity).
- The data is **in-memory only** — no database required. The array resets when the server restarts, and that is expected.
- Include a `package.json` with working `start` and `dev` scripts.
- Include a proper `.gitignore` that excludes `node_modules/`, `.env`, and other non-essential files. **Do not push `node_modules` to GitHub.**

```bash

# Create and switch to the new branch
```

### Commit & Push Rules

- **All commits and pushes must be done via the command line (CLI).** Commits made through the GitHub web UI will not count.
- **Every group member must have at least one meaningful commit** on the `REST-api-HW` branch. "Meaningful" means a commit that contributes real code or documentation — not just a blank line or whitespace change.
